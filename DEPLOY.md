# Deploying

Architecture: browser -> Vercel (static React app) -> `/api/*` rewritten to the Render API -> Neon Postgres.

The rewrite makes API calls same-origin from the browser's point of view. That matters: the session cookie is `SameSite=Lax`, which a separate API domain would silently break.

## 1. Database (Neon)
Use the `production` branch's `neondb` database. Migrations are applied automatically when the API boots (`prisma migrate deploy` in `render.yaml`). Keep a separate database or branch for tests; test runs wipe their tables.

## 2. API (Render)
1. Render dashboard -> New -> Blueprint -> pick this repo. It reads `render.yaml`.
2. Fill the prompted values:
   - `DATABASE_URL`: the Neon connection string (direct, not pooled, ends in `?sslmode=require`).
   - `ADMIN_EMAIL` / `ADMIN_PASSWORD`: the first admin, created on first boot if it does not exist. Use a strong password.
   - `WEB_ORIGIN`: the Vercel URL from step 3 (can be edited afterwards).
   - `JWT_SECRET` is generated by Render.
3. Wait for the deploy; check `https://<service>.onrender.com/api/health` returns `{"ok":true}`.

Free-tier note: the service sleeps after ~15 minutes idle; the first request afterwards takes about 30-60 seconds, and Neon's compute also needs a moment to wake.

## 3. Web (Vercel)
1. Vercel -> Add New Project -> import this repo. Leave the Root Directory as the repo root; `vercel.json` sets the install, build and output.
2. No environment variables needed.
3. If the Render service URL is not `https://wellness-streaks-api.onrender.com`, edit the destination in `vercel.json` and push.

## Smoke check after deploy
Log in with the admin, create a habit and a team, check in, and confirm the leaderboard shows the team.
